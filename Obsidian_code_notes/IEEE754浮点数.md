# IEEE 754 浮点数

## 名字的由来

**IEEE** = Institute of Electrical and Electronics Engineers（电气与电子工程师协会），一个制定技术标准的国际组织。

**754** = 这个标准在 IEEE 内部的编号，就像身份证号一样，没有特殊含义。该标准于 **1985 年**首次发布。

> 记忆技巧：IEEE（"我叫标准"）+ 754（"去误事"）→ 这个标准就是用来**去除浮点运算中可能误事**的精度问题。

## 为什么需要这个标准

IEEE 754 是浮点数运算的国际标准，几乎所有 CPU 和编程语言（C++ , Python , Java 等）都遵循它。

核心问题：**二进制无法精确表示某些十进制小数。**

就像十进制里 `1/3 = 0.333...` 永远写不完，二进制里 `0.1` 也是无限循环小数：

```
0.1（十进制）= 0.00011001100110011...（二进制，无限循环）
```

计算机只有有限的内存（32 或 64 位），只能**截断**后存储，于是产生一个极小的误差：

```python
0.1 + 0.2  # 不是 0.3，而是 0.30000000000000004
```

> 这不是 Python 的 bug，是硬件的物理限制。

## 结构

一个浮点数由三部分组成（以 64 位 double 为例）：

| 部分 | 位数 | 作用 |
|------|------|------|
| 符号位 | 1 位 | 正或负 |
| 指数 | 11 位 | 决定小数点的位置（"浮点"的含义） |
| 尾数 | 52 位 | 实际的有效数字 |

公式：

**值 = (-1)^符号 × (1.尾数) × 2^(指数 - 偏移量)**

> "浮点"的意思是小数点可以根据指数大小"浮动"，从而在很大和很小的数之间灵活表示。

## 实际影响

1. **别用 `==` 比较浮点数**，用"足够近"判断：
   ```python
   abs(a - b) < 1e-9  # 而不是 a == b
   ```

2. **需要精确小数时**（如金额），用 `Decimal` 模块或存成整数（分而非元）：
   ```python
   from decimal import Decimal
   Decimal('0.1') + Decimal('0.2')  # 精确等于 0.3
   ```

3. C++ 中 `float` 约 7 位有效数字，`double` 约 15 位——日常开发默认用 `double`。
