# 静态类型语言

## 定义

**静态类型语言**（Statically Typed Language）：编译时就知道每个变量的类型，类型检查在**编译期**完成。变量一旦声明了类型，之后不能存其他不兼容类型的值。

```cpp
int x = 42;      // x 是 int，编译时就确定了
x = "hello";     // ❌ 编译报错，int 不能存字符串
```

代表语言：**C++、C、Java、Rust、Go、TypeScript**

---

## 对比：动态类型语言

**动态类型语言**（Dynamically Typed Language）：类型检查在**运行期**，变量运行时可以随时绑定不同类型的值。

```python
x = 42           # x 是 int
x = "hello"      # OK，x 现在是 str
```

代表语言：**Python、JavaScript、Ruby、PHP**

---

## 静态 vs 动态

| | 静态类型 | 动态类型 |
|------|------|------|
| 类型检查时机 | 编译期 | 运行期 |
| 类型声明 | 必须（或编译器推导） | 不需要 |
| 类型错误发现 | 编译时就能发现 | 运行时才会报错 |
| 变量存不同类型 | ❌ 不行 | ✅ 可以 |
| 代码量 | 偏多（要写类型） | 偏少（省略类型） |
| 重构安全性 | 高，改类型编译器全报出来 | 低，容易遗漏 |
| 运行速度 | 快（编译时已知类型，生成高效代码） | 慢（运行时查类型） |
| IDE 支持 | 好（自动补全、跳转精确） | 弱（类型不确定） |

---

## 强类型 vs 弱类型

另一个容易混淆的概念：

- **强类型**：不允许隐式类型转换（或很少允许）
- **弱类型**：允许隐式类型转换

| | 静态 | 动态 |
|------|------|------|
| **强类型** | C++, Java, Rust | Python |
| **弱类型** | C (允许 `void*` 隐式转换) | JavaScript, PHP |

> C++ 总体是强类型，但 C 遗留的部分（如 `int` ↔ `char` 自动转换、`void*`）有弱类型特征。

---

## C++ 中的体现

### 1. 必须声明类型

```cpp
int x;          // 必须写类型
auto y = 42;    // auto 只是让编译器推导，编译后 y 还是 int，不能改
```

`auto` 不是动态类型——类型在编译时就定死了，只是不用手写而已。

### 2. 编译期检查

```cpp
void foo(int x) { ... }
foo("hello");   // ❌ 编译报错：参数类型不匹配
```

### 3. 类型贯穿整个生命周期

```cpp
int a = 1;
double b = a;   // OK，隐式转换（在编译期生成转换代码）
int *p = &b;    // ❌ 编译报错：类型不匹配
```

### 4. 静态类型的优势

更大的项目里面，静态类型带来的安全性非常关键：

```cpp
// 如果你改了函数签名：
void process(int id, const std::string &name);

// 所有调用 process(1, "hello") 的地方编译器全报出来
// 如果是 Python，要运行到那一行才知道炸了
```

> **一句话总结：静态类型是让编译器帮你盯代码，动态类型是相信自己不会写错。C++ 选前者。**

## Python 属于哪种？

Python 是**动态 + 强类型**。

### 动态类型

变量不带类型标签，运行时可以绑到任何类型的值上：

```python
x = 42           # x 是 int
x = "hello"      # OK，x 现在是 str
x = [1, 2, 3]    # OK，x 现在是 list
```

类型信息存在**值**上面，而不是**变量**上。`type(x)` 看的是 x 当前绑定的那个对象的类型。

### 强类型

不同类型之间不会自动隐式转换，这点和 C++ 不同：

```python
"hello" + 42     # ❌ TypeError，不会把 42 自动转成 "42"
1 + "2"          # ❌ TypeError，不会把 "2" 自动转成 int
```

> C++ 会默默做隐式转换而 Python 直接报错——这恰好说明 **"静态 vs 动态"和"强 vs 弱"是两个独立维度**。

### 类型提示（Python 3.5+）

Python 也支持可选的类型标注，但**不改变运行时行为**——解释器不检查类型，纯粹给人看和给工具用：

```python
def greet(name: str) -> str:
    return "Hello, " + name

greet(42)   # 运行时完全没问题，但 IDE/mypy 会提示
```

这是"渐进类型"——要加就加，不加也行。和 C++ 的类型约束比，Python 的类型提示更多是一种文档性质的存在。

### 三句话对比

| | C++ | Python |
|------|------|------|
| 类型检查 | 编译期强制 | 运行期动态 |
| 类型转换 | 允许隐式转换 | 强类型，基本禁止隐式转换 |
| 类型标注 | 强制 | 可选（类型提示，仅用于工具） |

> **C++ 是把类型当法律，Python 是把类型当建议。**
