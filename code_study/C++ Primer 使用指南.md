## 每章节的正确读法

以第 6 章为例：

1. **读一小节**（比如"6.2 参数传递"），不要一次读一整章
2. **打开 VS Code**，把书上的示例代码手敲一遍（禁止复制粘贴）
3. **编译运行**，看输出是否和书上一致
   ```bash
   g++ -Wall -Wextra -std=c++17 文件名.cpp -o 程序名
   ./程序名
   ```
4. **刻意修改代码**，观察行为变化：
   - 把传值 `void f(int a)` 改成传引用 `void f(int& a)`，看区别
   - 把非 const 引用改成 const 引用，看什么情况报错
   - 自己加点 `cout` 打印调试
5. **做章末练习题**，每题都写，写完才能对答案
6. **把练习题 commit 到 GitHub**

## 遇到看不懂的怎么办

### 不要卡住太久

一个概念如果看了 20 分钟还不懂，就跳过去。继续往下读。但要在学习笔记里记录下来：

```
2026-08-04：第6章参数传递看懂了，但const形参的部分没理解
明天再看一遍，或者换个角度搜索
```

过两天回头看，常常豁然开朗。

### 查资料的方法

- 用英文搜索：`c++ const member function meaning`（英文结果质量远高于中文）
- 在 [cppreference.com](https://en.cppreference.com/) 上查标准库的用法
- 用 ChatGPT 问"用大白话解释一下 C++ 的 const 成员函数，并举一个简单例子"——但只让它解释概念，不让它写你的练习题

## 重要的编译选项

养成用 Warning 编译的习惯，让编译器帮你找错误：

```bash
g++ -Wall -Wextra -std=c++17 -o output source.cpp
```

- `-Wall`：开启大部分警告
- `-Wextra`：开启额外警告
- `-std=c++17`：使用 C++17 标准（书上的 C++11 代码都能跑）

**每个 warning 都要搞懂，不能无视。** 警告往往就是潜在的 bug。
